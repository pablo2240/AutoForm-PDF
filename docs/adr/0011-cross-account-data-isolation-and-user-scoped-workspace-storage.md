# 0011: Cross-Account Data Isolation, User-Scoped Workspace Storage, and Stateless In-Memory Rendering

Establish strict cross-account tenant and user isolation across all document ingestion, workspace rendering, and download pipelines; eliminate global server filesystem state (`/input`, `active_slot.json`) in favor of authoritative Supabase Storage paths scoped to `(company_id, user_id)`, backed by a relational index `public.user_documents` with conditional hard-delete safeguards, database-enforced single-active-slot unique constraints, signed download URLs with anti-enumeration protection, and memory-only PyMuPDF stream rendering.

## Context & Problem
Previously, document handling in AutoForm PDF suffered from three severe cross-account isolation leaks:
1. **Unauthenticated Global Ingestion:** `POST /api/upload-pdf` lacked authentication dependencies and wrote incoming files into a flat server directory (`PROJECT_ROOT/input`).
2. **Global Shared State Collisions (`active_slot.json`):** Workspace selection was mediated by a single shared file on disk (`active_slot.json`). When User B uploaded a document, it overwrote or wiped out the active workspace of User A.
3. **Cross-Account Visibility and Unprotected Downloads:** `GET /api/templates`, `GET /api/pdf/{template_id}/pages`, and `GET /api/download/{filename}` did not check user ownership against session tokens. Any authenticated or unauthenticated user could inspect, render, or download files uploaded or generated by any other user on the instance.
4. **Container Ephemerality Vulnerability:** Files stored in Render's container disk (`/input`, `/output`) were wiped upon process recycles, contradicting durable persistence requirements.

## Decision

### 1. Hierarchical Tenant/User Isolation with Admin Auditability
- **Security Boundary:** All document operations require active authentication via `Depends(get_current_user)`.
- **Access Rule:** Commercial advisors (`role == 'commercial'`) have strict private visibility over their own uploaded documents (`auth.uid() = user_id`). Users with `role == 'admin'` in the same tenant can inspect and audit user documents and execution histories.
- **RLS Invariant:**
  ```sql
  CREATE POLICY "user_documents_isolation"
  ON public.user_documents FOR ALL
  USING (
      company_id = public.get_user_company_id()
      AND (user_id = auth.uid() OR public.is_admin())
  )
  WITH CHECK (
      company_id = public.get_user_company_id()
      AND user_id = auth.uid()
  );
  ```

### 2. Supabase Storage as Authoritative Store & Backend as Single Write Gate
- **Zero Client-Side Key Exposure:** File uploads never expose service-role credentials to the browser. The frontend transmits files over `authFetch` with bearer JWTs to `POST /api/upload-pdf`.
- **Pre-Persistence Verification:** The backend parses and validates incoming bytes using PyMuPDF (`fitz.open(stream=bytes, filetype="pdf")`) before committing to storage, immediately rejecting corrupt, unreadable, or malicious payloads.
- **Canonical Storage Topology:** Files are persisted in private Supabase Storage buckets under deterministic user namespaces:
  - Working Templates / Uploads: `templates/{company_id}/{user_id}/{filename}.pdf`
  - Generated Output PDFs: `generated-pdfs/{company_id}/{user_id}/{filename}.pdf`

### 3. Relational Index Table (`public.user_documents`) & Partial Unique Constraint
- Documents are indexed in PostgreSQL to ensure ACID properties, auditability, and fast retrieval without querying the Storage API on page loads:
  ```sql
  CREATE TABLE public.user_documents (
      id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      company_id UUID NOT NULL REFERENCES public.companies(id) ON DELETE RESTRICT,
      user_id UUID NOT NULL REFERENCES public.profiles(id) ON DELETE RESTRICT,
      template_code VARCHAR(100),
      filename VARCHAR(255) NOT NULL,
      storage_path VARCHAR(500) NOT NULL,
      size_kb NUMERIC(10, 1),
      is_active BOOLEAN NOT NULL DEFAULT true,
      created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
      updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
  );

  -- Database-enforced Single-File Slot guarantee
  CREATE UNIQUE INDEX idx_user_documents_single_active
  ON public.user_documents(user_id)
  WHERE is_active = true;

  -- High-frequency workspace lookup index
  CREATE INDEX idx_user_documents_user_active
  ON public.user_documents(user_id, is_active)
  WHERE is_active = true;
  ```

### 4. Safe Conditional Hard-Delete & Operational Ordering
- **Strict Execution Order:**
  1. Upload the newly incoming PDF to Supabase Storage.
  2. Transactionally update PostgreSQL to deactivate previous slots and activate the new record.
  3. Attempt post-commit cleanup of the superseded document only if `can_hard_delete(document_id)` returns true.
- **Comprehensive Reference Check (`can_hard_delete`):** Before deleting physical objects from Storage, inspect all dependent relational tables (including `form_fill_history`, mappings, exports, and active jobs). If referenced, preserve the record with `is_active = false`.
- **Storage Sweeper:** Orphaned storage artifacts caused by mid-flight crashes will be pruned by a scheduled maintenance sweeper.
- **Retention Policy:** Documents retained for legal audit will not be automatically purged until an explicit corporate data retention policy is defined by IAC legal counsel.

### 5. Total Purge of Legacy Shared State (`/input`, `active_slot.json`)
- **Pre-Purge SHA-256 Audit:** Verify that all 4 canonical corporate templates sitting in `/input` match the checksums in `pdf_templates`.
- **Fail-Closed Code Removal:** All code reading `active_slot.json` is completely eradicated. If any component attempts to read legacy un-scoped state, it fails closed with an explicit error.
- **Repository Cleanliness:** `/input` and `active_slot.json` are added to `.gitignore`.

### 6. Stateless In-Memory Page Rendering
- **RAM-Only Processing:** Page rendering avoids temporary server disk writes, opening bytes directly from Supabase Storage via `fitz.open(stream=bytes, filetype="pdf")`.
- **Demand-Paging & Quota Protection:** Render individual pages on demand rather than buffering multi-page documents simultaneously in RAM.
- **Browser Caching:** Emit `ETag` and `Cache-Control: private, max-age=3600` headers to leverage browser memory rather than server disk.
- **Authorization Verification:** The backend verifies that `document_id` belongs to `auth.uid()` or an admin before requesting storage streams.

### 7. Protected Downloads with Signed URLs and Anti-Enumeration
- Replace unauthenticated `GET /api/download/{filename}` with authenticated `GET /api/download/{history_id}`.
- Verify ownership against `form_fill_history.operator_user_id` or tenant admin status.
- Return time-limited signed URLs (`create_signed_url(..., expires_in=600)`) from Supabase Storage.
- Enforce blind anti-enumeration errors (returning HTTP 404/403 uniformly).

### 8. Hybrid Institutional Template Binding (Safe Passivity)
- When a user uploads a document whose normalized name matches an institutional template in `public.pdf_templates`, pre-populate visual boxes from `pdf_mappings`.
- Display a prominent visual badge (*"Plantilla Institucional vinculada"*), requiring operator visual verification before stamping, adhering to the project's Safe Passivity principle.

## Consequences

### Positive
- Complete eradication of cross-account document leakage and shared slot collisions.
- True multi-tenant isolation adhering to Colombian data privacy regulations (Ley 1581 / Habeas Data).
- Zero reliance on ephemeral container disks in Render; documents persist reliably in Supabase Storage.
- Single-active-slot invariant enforced at the database level by unique partial index.
- Elimination of unauthenticated file download attack vectors.

### Negative / Trade-offs
- File uploads require an additional network round-trip from the backend to Supabase Storage before returning.
- Multi-page rendering requires stream fetching from Storage unless cached in browser memory via ETags.
